# Mobile-Responsive Damage Calculator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the damage calculator usable with full feature parity on phones and tablets down to ~360px, across all five pages, via an additive CSS layer that leaves desktop untouched.

**Architecture:** Append a single `/* Responsive */` section of `@media` rules to `src/css/main.css`, plus one viewport-meta change in `src/shared.template.html`. No existing desktop CSS rule, HTML structure, or JS is modified. Two breakpoints: a "stack" breakpoint at `max-width: 1080px` (three float-columns become a single stacked column) and a "phone" breakpoint at `max-width: 480px` (fixed-`em` control widths become fluid).

**Tech Stack:** Static HTML + hand-written CSS (no preprocessor), jQuery + select2 controls, a Node build script (`build`) that injects `shared.template.html`'s `<head>` into each page and copies `src/` → `dist/`. Local preview: `npm run build-ui` then `node server.js` (serves `dist/` on `http://localhost:3000`).

## Global Constraints

- **Additive only.** Do not modify or delete any existing rule in `src/css/main.css`. Only append a new `/* Responsive */` section at the end of the file. The sole non-CSS edit is the viewport meta line.
- **No HTML structure or JS changes.** The jQuery controls key off classes/IDs, not layout. The one allowed HTML edit is the single viewport `<meta>` attribute in `src/shared.template.html`.
- **No vendor-file edits.** Do not touch `src/css/vendor/bootstrap.css` or `src/js/vendor/select2/select2.css`. Override vendor widths via our own scoped selectors.
- **Desktop must not regress.** All new rules live behind `@media (max-width: …)`. Verify the layout at >1080px is visually identical to `master`.
- **Viewport edit goes in `src/shared.template.html` only** — the build regenerates each page's `<head>` from that template, so editing individual pages would be overwritten.
- **Root font-size is `10pt` (~13.3px).** `1em` ≈ 13.3px in body-level rules; keep this in mind when choosing `em` widths.
- Run `npm run lint` before the final commit; it must pass.

## Preview workflow (used by every task's verification)

1. Build: `npm run build-ui` (runs `node build view`; copies `src/` → `dist/` and injects the template head). Use this rather than `npm run build` to skip the slower `@smogon/calc` recompile — layout CSS lives in `dist/css/main.css` either way.
2. Serve: `node server.js` (background), then open `http://localhost:3000/index.html`.
3. In the browser devtools, toggle the device toolbar (Ctrl+Shift+M in Chrome) and set a **responsive** viewport, typing exact widths (360, 414, 768, 1080) into the width field. Also test full desktop width (e.g. 1400).
4. "No horizontal scroll" means: at the given width, the page body does not scroll sideways and no control is clipped off-screen.

> The engineer must rebuild (`npm run build-ui`) after each `src/` edit before re-checking the browser, because the server serves `dist/`, not `src/`.

### Task 1: Viewport + "stack" breakpoint (1080px) for the four standard pages

**Interfaces:**
- Consumes: nothing (first task).
- Produces: a `/* Responsive */` section ending the file, containing an `@media (max-width: 1080px) { … }` block that Tasks 2–4 will sit beside (Task 2 adds a separate `@media (max-width: 480px)` block; Task 3 extends that block; Task 4 relies on the `.flex-parent { flex-wrap: wrap }` rule added here).

Append to the very end of `src/css/main.css`:

```css
/*********************************************************
 * Responsive

    /* Remove the desktop min-widths that force horizontal scroll */

        min-width: 0;

        float: none;
        width: 100%;
        max-width: 34em;
        margin: 0 auto 1em;
        box-sizing: border-box;

    .flex-parent {
        flex-wrap: wrap;
    }

    /* Enlarge the tiny toggle buttons to comfortable tap targets */
    .poke-info .crit-btn,
    .poke-info .z-btn,
    .poke-info .max-btn,
```

### Task 2: "Phone" breakpoint (480px) — fluidize controls

Below 480px, replace the fixed-`em` widths on selects, the move-result columns, and the import textareas with fluid widths so nothing overflows a 360px screen.

**Files:**
- Modify: `src/css/main.css` (add a new `@media (max-width: 480px)` block after the 1080px block from Task 1)

**Interfaces:**
- Consumes: the stacked single-column layout from Task 1 (panels are already full-width at this width).
- Produces: the `@media (max-width: 480px) { … }` block that Task 3 extends with stat-table rules.

- [ ] **Step 1: Append the phone breakpoint to `main.css`**

Append after the `@media (max-width: 1080px)` block:

```css
@media (max-width: 480px) {
    /* Let panels use the full narrow width */
    .poke-info,
    .field-info,
    .poke-import {
        max-width: none;
    }

    /* Stack the two move-result columns */
    .move-result-subgroup {
        float: none;
        width: 100%;
    }

    /* Fluidize the fixed-width selects and set selector */
    .set-selector,
    .info-selectors select,
    .move-selector {
        width: 100%;
        box-sizing: border-box;
    }
    /* select2 renders its own container; force it to the parent width */
    .select2-container {
        width: 100% !important;
    }

    /* Fluidize the import textareas */
    .import-team-text,
    .import-name-text {
        min-width: 0;
        width: 100%;
        box-sizing: border-box;
    }
}
```

- [ ] **Step 2: Rebuild and reload**

Run: `npm run build-ui` (the background server keeps serving the updated `dist/`).
Expected: build prints `DONE` with no error.

### Task 3: Tighten the stat table at phone widths

The `HP | Base | IVs | EVs | total` stat table is the densest element and is the last thing overflowing 360px. Constrain its inputs and padding so the row fits.

**Files:**
- Modify: `src/css/main.css` (add rules *inside* the existing `@media (max-width: 480px)` block from Task 2)

**Interfaces:**
- Consumes: the `@media (max-width: 480px)` block from Task 2.
- Produces: nothing consumed by later tasks.

- [ ] **Step 1: Add stat-table rules inside the 480px block**

Inside the `@media (max-width: 480px) { … }` block (before its closing brace), add:

```css
    /* Tighten the stat table so the HP/Base/IVs/EVs/total row fits ~360px */
    .poke-info th,
    .poke-info td {
        padding: 0 1px;
    }
    .poke-info input.base,
    .poke-info input.ivs,
    .poke-info input.dvs {
        width: 3em;
        box-sizing: border-box;
    }
    .poke-info input.evs[type="number"] {
        width: 3.5em;
        box-sizing: border-box;
    }
```

**Selector note (do not "simplify" these):** the desktop base rule is
`.poke-info input:not([type])` — specificity (0,2,1). A shorter override like
`.poke-info .base` is (0,2,0) and **loses** (media queries add no specificity).
`.poke-info input.base` ties at (0,2,1) and wins by source order because it comes later in
the file. Do not use `table-layout: fixed` on `.poke-info table`: it distributes the seven
columns evenly (~51px each at 360px), which clips the "Sp. Atk"/"Sp. Def" label column.

Expected: `DONE`, no error.

- [ ] **Step 4: Verify at 320px (stress test)**
